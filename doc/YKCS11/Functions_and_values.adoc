Not all PKCS#11 Object types are implemented. This is a list of what is
implemented and what it maps to.

The attributes that describe a particular kind of key are only readable from a key of that kind: CKA_MODULUS,
CKA_MODULUS_BITS and CKA_PUBLIC_EXPONENT from RSA keys, CKA_EC_POINT and CKA_EC_PARAMS from EC keys, and
CKA_PARAMETER_SET from ML-DSA and ML-KEM keys. Reading one of them from a key of another kind returns
CKR_ATTRIBUTE_TYPE_INVALID.

CKA_ENCAPSULATE and CKA_DECAPSULATE work differently: they are readable from any public respectively private key and
are CK_TRUE for ML-KEM keys and CK_FALSE for everything else. PKCS#11 v3.2 makes them the precondition for calling
C_EncapsulateKey and C_DecapsulateKey, so an application can use them to find the ML-KEM keys on the token without
looking at CKA_KEY_TYPE.

CKA_YUBICO_TOUCH_POLICY and CKA_YUBICO_PIN_POLICY are vendor defined attributes. They return the touch and PIN policy
of the slot as a single byte each, using the values of YKPIV_TOUCHPOLICY_* and YKPIV_PINPOLICY_* from `ykpiv.h`.
